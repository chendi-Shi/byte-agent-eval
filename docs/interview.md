# 面试讲述与演示

建议先用一句话说明任务：“我实现了一个服务诊断 Agent 的独立评测体系，
要求它查实际指标、运行手册和变化记录，再把开发数据与小模型 SFT／RL
连起来；每条分数和训练权重都有可追溯证据。”

## 五分钟演示

1. 打开一条原 Qwen trace，展示目标 service、三种实际工具调用和最终 JSON。
   从 [模型实测记录](../examples/model-results.md) 进入成功与失败记录。
2. 打开独立 oracle 的 checks，说明格式、数值、当前来源和原因／建议都要
   正确。模型输出“成功”不算验收通过，verified validator 也不读取 gold
   诊断标签。
3. 展示 prompt 对照与 no-changes 消融，解释为什么删工具的完整成功率
   差值有机械完整性影响，因此要同时看决策指标与原始失败。
4. 展示训练 `partition.json` 和 `candidate-review.json`：18 个开发训练
   服务与 6 个验证、8 个公开留出服务分开；原 8 条 Qwen 长轨迹仍需人工
   审查，小模型的 72 条监督动作明确属于 synthetic-supervised。
5. 打开 [训练报告](../examples/experiments/training-v3/report.md)、
   [summary](../examples/experiments/training-v3/summary.json)、实际 sampled
   episode 与 adapter 哈希，展示 SFT／RL 的 loss、reward、真实梯度和
   参数变化。先讲实际前后结果，再解释结果支持什么结论。

## 容易被追问的设计问题

**为什么不用模型自己当唯一裁判？** 当前任务有严格可验收的数值、证据
和枚举决策，独立 oracle 能检查实际执行记录，避免把流畅解释当作完成。
它不替代开放式文本评价，也不能证明生产因果关系。

**小模型为什么只生成动作字母？** CPU 资源有限，实验重点是验证工具选择
和执行奖励能否真实反传到预训练语言模型。字母使用原 LM 词表 logits，
梯度更新 q/v LoRA；服务、参数、数值和引用由 host 绑定／渲染。因此结果
明确限定为受约束策略，不能和原 Qwen 自由 JSON 成功率混比。

**怎么证明 RL 真训练了语言模型？** 保存初始／SFT／RL adapter，列出
参数及文件哈希；RL 清除 SFT 优化器动量，默认熵项为零，要求 reward
advantage、梯度和参数变化都非零。重新加载前扰动所有 LoRA tensor，
要求完全恢复。训练使用实际执行工具的 sampled episode，不是离线 bandit
路由器或导出数据冒充训练。

**如何避免评测标签泄漏？** 模型状态只取 service、动作历史和实际工具
返回的摘要。开发教师标签只用于监督目标及终端奖励；验证和留出不参与
训练。公开留出仍然没有保密性，所以只报告服务隔离与合成场景表现。

**分数没提高怎么办？** 保留零提升或负提升、各条失败和训练配置，分析
是工具规划、终止时机还是诊断类别导致失败。实际参数优化完成与能力提升
是两项独立结论，不能依据测试结果反复改超参数再声称一次独立验证。

可复现命令与完整方法见 [训练说明](training.md)。简历应采用实际报告中的
结果、口径和限制，不把“实现了训练流程”改写成“优化了原 Qwen 4B”或
“上线后显著提高生产效率”。
